Loads the full LUCAS 2009 campaign — sampling log, geolocations, samples, observation logs, lab-measured soil properties, and spectral observations — from the files `lucas_2009_to_xspatula.py` generated.

## Notebook

**Path**: `xspatula_lucas/lucas/import_data/load_LUCAS_2009.ipynb`

Run these eight cells, each pointing to a `job_file` under `import_data/LUCAS_2009/`, **in this fixed order** — later steps depend on earlier ones by foreign keys:

| # | Cell | Job file | Detail |
|---|---|---|---|
| 1 | Manage LUCAS 2009 sampling log | `job_LUCAS_2009_sampling_log.json` | — |
| 2 | Manage LUCAS 2009 geolocations | `job_LUCAS_2009_geolocation.json` | [Samples explained] |
| 3 | Manage LUCAS 2009 samples | `job_LUCAS_2009_sample.json` | [Samples explained] |
| 4 | Manage LUCAS 2009 laboratory observation log | `job_LUCAS_2009_observation_log_lab.json` | [below](#lab-observation-log-and-observations) |
| 5 | Manage LUCAS 2009 laboratory observations | `job_LUCAS_2009_observation_lab.json` | [below](#lab-observation-log-and-observations) |
| 6 | Manage LUCAS 2009 spectrometer | `job_LUCAS_2009_spectrometer.json` | [Observations explained] |
| 7 | Manage LUCAS 2009 spectra observation logs | `job_LUCAS_2009_observation_log_spectra.json` | [Observations explained] |
| 8 | Manage LUCAS 2009 spectra observations | `job_LUCAS_2009_observation_spectra.json` | [Observations explained] |

Set `scheme_file = '../scheme_lucas.json'` in the setup cell (already the default), then run the
notebook top to bottom. This page covers the two steps unique to this pipeline — lab observations — in full; the geolocation, sample, spectrometer, and spectral-observation steps are documented in
depth in [Samples explained] and [Observations explained], which are reference pages you don't
need to read to complete the walkthrough.

## Lab observation log and observations

LUCAS 2009 ships pre-measured lab soil properties directly in the source CSV — there's no
separate wetlab workflow or instrument to register, just one observation log and one observation
record per sample.

### Observation log (cell 4)

Links the campaign's sampling log to the `lucas-wetlab-2009` provision — the lab analysis
"instrument," in Xspatula's terms, even though it's really a set of standard lab methods rather
than a single physical device.

Generated by `lucas_2009_to_xspatula.py`, `step2_observation_log()`, written to
`process_lab/observation_log/manage_process/lucas_eu_2009@lucas-wetlab-2009_observation_log.json`:

```json
{
  "process": [
    {
      "process": "manage_observation_log",
      "parameters": {
        "sampling_log_id__sampling_log_name": "lucas_eu_2009",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "name": "lucas_eu_2009@lucas-wetlab-2009",
        "contact_name": "thomas gumbricht",
        "contact_email": "thomas.gumbricht@gmail.com",
        "preparation_id__preparation_name": "ds2",
        "preservation_id__preservation_name": "ds2",
        "storage_id__storage_name": "amb",
        "laboratory": 1
      }
    }
  ]
}
```

### Observations (cell 5)

One record per CSV row that has at least one measured indicator. Generated by
`step6_lab_observation()`, one process file per sample under `process_lab/observation/manage_process/`:

```json
{
  "process": [
    {
      "process": "manage_observation",
      "parameters": {
        "observation_log_id__observation_log_name": "lucas_eu_2009@lucas-wetlab-2009",
        "sample_id__sample_name": "<POINT_ID>@0-20",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "subsample": "a",
        "replicate": 0,
        "observed_at": "<date, ISO 8601>",
        "@cf": "<coarse fragment %>",
        "@clay": "<clay %>",
        "@silt": "<silt %>",
        "@sand": "<sand %>",
        "@ph-cacl2": "<pH in CaCl2>",
        "@ph-h2o": "<pH in H2O>",
        "@c-org": "<organic carbon>",
        "@caco3": "<CaCO3>",
        "@n-tot": "<total nitrogen>",
        "@p-ext": "<extractable phosphorus>",
        "@k-ext": "<extractable potassium>",
        "@cec": "<cation exchange capacity>"
      }
    }
  ]
}
```

Any indicator column that's missing or unparseable (`NA` in the source CSV) in a given row is
simply omitted from that row's parameters — the `@`-prefixed indicator keys are optional, not
fixed-width.

| CSV column | Parameter | Indicator |
|---|---|---|
| `coarse` | `@cf` | Coarse fragments |
| `clay` | `@clay` | Clay content |
| `silt` | `@silt` | Silt content |
| `sand` | `@sand` | Sand content |
| `pH.in.CaCl2` | `@ph-cacl2` | pH in CaCl₂ |
| `pH.in.H2O` | `@ph-h2o` | pH in H₂O |
| `OC` | `@c-org` | Organic carbon |
| `CaCO3` | `@caco3` | Calcium carbonate |
| `N` | `@n-tot` | Total nitrogen |
| `P` | `@p-ext` | Extractable phosphorus |
| `K` | `@k-ext` | Extractable potassium |
| `CEC` | `@cec` | Cation exchange capacity |

## Spectra observation log and observations

LUCAS 2009 samples were scanned on a FOSS XDS Rapid Content Analyzer. Unlike the lab
observations above, spectral data needs one extra step first: registering the instrument's
wavelength axis.

### Spectrometer (cell 6)

Registers the FOSS XDS RCA's wavelength axis — the array of wavelengths every spectral
observation's reflectance array is ordered against. Generated by `step3_spectrometer()`, written
to `process_spectra/spectrometer/manage_process/foss-xds-rca_lucas 2009_spectrometer.json`:

```json
{
  "process": [
    {
      "process": "manage_spectrometer",
      "parameters": {
        "provision_id__provision_name": "foss xds rca",
        "wavelength_array": ["<one float per spc.* column in the source CSV>"],
        "wavelength_unit_id__wavelength_unit_name": "um",
        "provision_serial_nr_id__provision_serial_nr_name": "lucas 2009"
      }
    }
  ]
}
```

The wavelength array's column order defines the position each value in an observation's
`@diffuse reflectance` array corresponds to — they must stay in lockstep, and both are built from
the same `spc.*` column iteration in the source CSV.

### Observation log (cell 7)

Links the campaign's sampling log to the spectrometer's provision — one record for all FOSS XDS
RCA scans in the campaign. Generated by `step2_observation_log()`, written to
`process_spectra/observation_log/manage_process/lucas_eu_2009@foss xds rca_observation_log.json`:

```json
{
  "process": [
    {
      "process": "manage_observation_log",
      "parameters": {
        "sampling_log_id__sampling_log_name": "lucas_eu_2009",
        "provision_id__provision_name": "foss xds rca",
        "name": "lucas_eu_2009@foss xds rca",
        "contact_name": "thomas gumbricht",
        "contact_email": "thomas.gumbricht@gmail.com",
        "preparation_id__preparation_name": "ds2",
        "preservation_id__preservation_name": "ds2",
        "storage_id__storage_name": "amb",
        "laboratory": 1
      }
    }
  ]
}
```

### Observations (cell 8)

One record per CSV row — a diffuse-reflectance array derived from the source CSV's `spc.*`
absorbance columns. Generated by `step7_spectra_observation()`, one process file per sample under
`process_spectra/observation/manage_process/`:

```json
{
  "process": [
    {
      "process": "manage_observation",
      "parameters": {
        "observation_log_id__observation_log_name": "lucas_eu_2009@foss xds rca",
        "sample_id__sample_name": "<POINT_ID>@0-20",
        "provision_id__provision_name": "foss xds rca",
        "subsample": "a",
        "replicate": 0,
        "observed_at": "<date, ISO 8601>",
        "provision_serial_nr_id__provision_serial_nr_name": "lucas 2009",
        "@diffuse reflectance": ["<one float per spc.* column, 1/exp(absorbance)>"]
      }
    }
  ]
}
```

`subsample`/`replicate` are fixed at `a`/`0` — LUCAS 2009 ships one scan per sample. See
[Observations explained] for the full parameter table and how the reflectance array is derived.
