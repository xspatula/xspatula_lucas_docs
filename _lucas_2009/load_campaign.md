Runs the full LUCAS 2009 campaign — sampling log, geolocations, samples, lab-measured soil
properties, and spectral observations — from the files `lucas_2009_to_xspatula.py` generated.

## Notebook

**Path**: `xspatula_lucas/lucas/import_data/load_LUCAS.ipynb`

Nine cells, each a `job_file` pointing at one of the generated job files under
`import_data/LUCAS_2009/`, run **in this fixed order** — later steps depend on earlier ones by
foreign key:

| # | Cell | Job file | Detail |
|---|---|---|---|
| 1 | Manage LUCAS campaigns | `job_LUCAS_2009_campaign.json` | see [caveat below](#campaign-and-sampling-log) |
| 2 | Manage LUCAS sampling logs | `job_LUCAS_2009_sampling_log.json` | see [caveat below](#campaign-and-sampling-log) |
| 3 | Manage LUCAS geolocations | `job_LUCAS_2009_geolocation.json` | [Manage geolocation] |
| 4 | Manage LUCAS samples | `job_LUCAS_2009_sample.json` | [Manage sample] |
| 5 | Manage LUCAS laboratory observation logs | `job_LUCAS_2009_observation_log_lab.json` | [below](#lab-observation-log-and-observations) |
| 6 | Manage LUCAS laboratory observations | `job_LUCAS_2009_observation_lab.json` | [below](#lab-observation-log-and-observations) |
| 7 | Manage LUCAS spectrometer | `job_LUCAS_2009_spectrometer.json` | [Manage spectrometer] |
| 8 | Manage LUCAS spectra observation logs | `job_LUCAS_2009_observation_log_spectra.json` | [Manage observation log] |
| 9 | Manage LUCAS spectra observations | `job_LUCAS_2009_observation_spectra.json` | [Manage observation] |

Set `scheme_file = '../scheme_lucas.json'` in the setup cell (already the default), then run all
nine cells top to bottom. Cells 3–4 and 7–9 are documented in full, with process-file examples and
parameter tables, in [Sample][sample] and [Spectra][spectra] respectively — this page covers the
two cells (1–2) that need a caveat, and the two (5–6) unique to this pipeline: lab observations.

## Campaign and sampling log

Cells 1–2 run `manage_campaign` and `manage_sampling_log` against the `process_lab/campaign/` and
`process_lab/sampling_log/` files `lucas_2009_to_xspatula.py` generated — **not** the `campaign.xlsx`
row from [Insert dataset metadata][insert_dataset_meta]. Both target the same campaign name
(`lucas_eu_2009`) with different data (notably, a narrower `provision_id__provision_name_array`
here). See [Dataset metadata → Manage campaign][manage_campaign] for the full explanation and what
to check before running both against the same database.

`manage_sampling_log` has no such overlap — it's only ever generated and loaded through this
pipeline, never through the dataset-metadata Excel route.

## Lab observation log and observations

LUCAS 2009 ships pre-measured lab soil properties directly in the source CSV — there's no
separate wetlab workflow or instrument to register, just one observation log and one observation
record per sample.

### Observation log (cell 5)

Links the campaign's sampling log to the `lucas-wetlab-2009` provision — the lab analysis
"instrument," in Xspatula's terms, even though it's really a set of standard lab methods rather
than a single physical device.

Generated by `lucas_2009_to_xspatula.py`, `step2_observation_log()`, written to
`process_lab/observation_log/manage_process/lucas_eu_2009@lucas-wetlab-2009_observation_log.json`:

```json
{
  "process": [
    {
      "process": "manage_observation_log",
      "parameters": {
        "sampling_log_id__sampling_log_name": "lucas_eu_2009",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "name": "lucas_eu_2009@lucas-wetlab-2009",
        "contact_name": "thomas gumbricht",
        "contact_email": "thomas.gumbricht@gmail.com",
        "preparation_id__preparation_name": "ds2",
        "preservation_id__preservation_name": "ds2",
        "storage_id__storage_name": "amb",
        "laboratory": 1
      }
    }
  ]
}
```

### Observations (cell 6)

One record per CSV row that has at least one measured indicator. Generated by
`step6_lab_observation()`, one process file per sample under `process_lab/observation/manage_process/`:

```json
{
  "process": [
    {
      "process": "manage_observation",
      "parameters": {
        "observation_log_id__observation_log_name": "lucas_eu_2009@lucas-wetlab-2009",
        "sample_id__sample_name": "<POINT_ID>@0-20",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "subsample": "a",
        "replicate": 0,
        "observed_at": "<date, ISO 8601>",
        "@cf": "<coarse fragment %>",
        "@clay": "<clay %>",
        "@silt": "<silt %>",
        "@sand": "<sand %>",
        "@ph-cacl2": "<pH in CaCl2>",
        "@ph-h2o": "<pH in H2O>",
        "@c-org": "<organic carbon>",
        "@caco3": "<CaCO3>",
        "@n-tot": "<total nitrogen>",
        "@p-ext": "<extractable phosphorus>",
        "@k-ext": "<extractable potassium>",
        "@cec": "<cation exchange capacity>"
      }
    }
  ]
}
```

Any indicator column that's missing or unparseable (`NA` in the source CSV) in a given row is
simply omitted from that row's parameters — the `@`-prefixed indicator keys are optional, not
fixed-width.

| CSV column | Parameter | Indicator |
|---|---|---|
| `coarse` | `@cf` | Coarse fragments |
| `clay` | `@clay` | Clay content |
| `silt` | `@silt` | Silt content |
| `sand` | `@sand` | Sand content |
| `pH.in.CaCl2` | `@ph-cacl2` | pH in CaCl₂ |
| `pH.in.H2O` | `@ph-h2o` | pH in H₂O |
| `OC` | `@c-org` | Organic carbon |
| `CaCO3` | `@caco3` | Calcium carbonate |
| `N` | `@n-tot` | Total nitrogen |
| `P` | `@p-ext` | Extractable phosphorus |
| `K` | `@k-ext` | Extractable potassium |
| `CEC` | `@cec` | Cation exchange capacity |
