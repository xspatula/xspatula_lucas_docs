Reference page — not required reading to complete the [Load LUCAS 2009][load_lucas_2009]
walkthrough, only if you want the detail behind its observation-log and observation steps.

## Two kinds of observation

LUCAS 2009 records two different shapes of measurement, and the underlying `manage_observation`
process stores them in different tables depending on the shape of the `@`-prefixed parameter
value it's given:

| Measurement shape | Example | Stored in |
|---|---|---|
| Single value per indicator (laboratory) | `@ph-h2o: 6.8` | `observation.observation_measurement` |
| Array per indicator (spectra) | `@diffuse reflectance: [0.34, 0.34, ...]` | `observation.observation_measurement_array` |

Both kinds share the same `observation.observation` record shape otherwise — an observation log,
sample, provision, subsample, replicate, and timestamp — the only difference is which child table
the indicator's value lands in.

## Laboratory observations

LUCAS 2009 ships pre-measured lab soil properties directly in the source CSV — there's no
separate wetlab workflow or instrument to register, just one observation log and one observation
record per sample, both generated by `lucas_2009_to_xspatula.py`.

### Observation log

Links the campaign's sampling log to the `lucas-wetlab-2009` provision — the lab analysis
"instrument," in Xspatula's terms, even though it's really a set of standard lab methods rather
than a single physical device.

**Job file**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_observation_log_lab.json`

```json
{
  "process": {
    "job_folder": "import_data/LUCAS_2009/process_lab/observation_log",
    "process_sub_folder": "manage_process",
    "pilot_file": "xspatula_add_observation_log_pilot.txt"
  }
}
```

**Generated by**: `step2_observation_log()`, written to
`process_lab/observation_log/manage_process/lucas_eu_2009@lucas-wetlab-2009_observation_log.json`:

```json
{
  "process": [
    {
      "process": "manage_observation_log",
      "parameters": {
        "sampling_log_id__sampling_log_name": "lucas_eu_2009",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "name": "lucas_eu_2009@lucas-wetlab-2009",
        "contact_name": "inherit",
        "contact_email": "inherit",
        "preparation_id__preparation_name": "ds2",
        "preservation_id__preservation_name": "ds2",
        "storage_id__storage_name": "amb",
        "laboratory": 1
      }
    }
  ]
}
```

### Observations

One record per CSV row that has at least one measured indicator. Each `@`-prefixed indicator
value below is a single number, stored in `observation.observation_measurement`.

**Job file**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_observation_lab.json`

```json
{
  "process": {
    "job_folder": "import_data/LUCAS_2009/process_lab/observation",
    "process_sub_folder": "manage_process",
    "pilot_file": "xspatula_add_observation_pilot.txt"
  }
}
```

**Generated by**: `step6_lab_observation()`, one process file per sample under
`process_lab/observation/manage_process/`:

```json
{
  "process": [
    {
      "process": "manage_observation",
      "parameters": {
        "observation_log_id__observation_log_name": "lucas_eu_2009@lucas-wetlab-2009",
        "sample_id__sample_name": "<POINT_ID>@0-20",
        "provision_id__provision_name": "lucas-wetlab-2009",
        "subsample": "a",
        "replicate": 0,
        "observed_at": "<date, ISO 8601>",
        "@cf": "<coarse fragment %>",
        "@clay": "<clay %>",
        "@silt": "<silt %>",
        "@sand": "<sand %>",
        "@ph-cacl2": "<pH in CaCl2>",
        "@ph-h2o": "<pH in H2O>",
        "@c-org": "<organic carbon>",
        "@caco3": "<CaCO3>",
        "@n-tot": "<total nitrogen>",
        "@p-ext": "<extractable phosphorus>",
        "@k-ext": "<extractable potassium>",
        "@cec": "<cation exchange capacity>"
      }
    }
  ]
}
```

Any indicator column that's missing or unparseable (`NA` in the source CSV) in a given row is
simply omitted from that row's parameters — the `@`-prefixed indicator keys are optional, not
fixed-width.

| CSV column | Parameter | Indicator |
|---|---|---|
| `coarse` | `@cf` | Coarse fragments |
| `clay` | `@clay` | Clay content |
| `silt` | `@silt` | Silt content |
| `sand` | `@sand` | Sand content |
| `pH.in.CaCl2` | `@ph-cacl2` | pH in CaCl₂ |
| `pH.in.H2O` | `@ph-h2o` | pH in H₂O |
| `OC` | `@c-org` | Organic carbon |
| `CaCO3` | `@caco3` | Calcium carbonate |
| `N` | `@n-tot` | Total nitrogen |
| `P` | `@p-ext` | Extractable phosphorus |
| `K` | `@k-ext` | Extractable potassium |
| `CEC` | `@cec` | Cation exchange capacity |

## Spectral observations

LUCAS 2009 soil samples were scanned on a FOSS XDS Rapid Content Analyzer. Spectral data is
stored as a diffuse-reflectance array per sample scan, generated from the source CSV's `spc.*`
columns by `lucas_2009_to_xspatula.py` — see [Prepare data]. Unlike the lab observations above,
spectral data needs one extra step first: registering the instrument's wavelength axis.

| Instrument | Provision | Provision ID |
|---|---|---|
| FOSS XDS Rapid Content Analyzer | `foss xds rca` | `foss-xds-rca` |

### Spectrometer

Registers the instrument's wavelength axis — the array of wavelengths every spectral
observation's reflectance array is ordered against.

**Job file**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_spectrometer.json`

```json
{
  "process": {
    "job_folder": "import_data/LUCAS_2009/process_spectra/spectrometer",
    "process_sub_folder": "manage_process",
    "pilot_file": "xspatula_add_spectrometer_pilot.txt"
  }
}
```

**Generated by**: `step3_spectrometer()`. Process file
(`.../process_spectra/spectrometer/manage_process/foss-xds-rca_lucas 2009_spectrometer.json`):

```json
{
  "process": [
    {
      "process": "manage_spectrometer",
      "parameters": {
        "provision_id__provision_name": "foss xds rca",
        "wavelength_array": ["<one float per spc.* column in the source CSV>"],
        "wavelength_unit_id__wavelength_unit_name": "um",
        "provision_serial_nr_id__provision_serial_nr_name": "lucas 2009"
      }
    }
  ]
}
```

| Parameter | Description |
|---|---|
| `provision_id__provision_name` | `foss xds rca` — the instrument provision |
| `wavelength_array` | One value per `spc.<wavelength>` column in `LUCAS.SOIL_corr.csv`, in file column order |
| `wavelength_unit_id__wavelength_unit_name` | `um` |
| `provision_serial_nr_id__provision_serial_nr_name` | `lucas 2009` — placeholder serial number, since LUCAS 2009 used multiple physical instruments across labs |

The wavelength array's column order defines the position each value in an observation's
`@diffuse reflectance` array corresponds to — they must stay in lockstep.

### Observation log

Links the campaign's sampling log to the spectrometer's provision — one record for all FOSS XDS
RCA scans in the LUCAS 2009 campaign.

**Job file**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_observation_log_spectra.json`

```json
{
  "process": {
    "job_folder": "import_data/LUCAS_2009/process_spectra/observation_log",
    "process_sub_folder": "manage_process",
    "pilot_file": "xspatula_add_observation_log_pilot.txt"
  }
}
```

**Generated by**: `step2_observation_log()`. Process file
(`.../process_spectra/observation_log/manage_process/lucas_eu_2009@foss xds rca_observation_log.json`):

```json
{
  "process": [
    {
      "process": "manage_observation_log",
      "parameters": {
        "sampling_log_id__sampling_log_name": "lucas_eu_2009",
        "provision_id__provision_name": "foss xds rca",
        "name": "lucas_eu_2009@foss xds rca",
        "contact_name": "inherit",
        "contact_email": "inherit",
        "preparation_id__preparation_name": "ds2",
        "preservation_id__preservation_name": "ds2",
        "storage_id__storage_name": "amb",
        "laboratory": 1
      }
    }
  ]
}
```

| Parameter | Description |
|---|---|
| `sampling_log_id__sampling_log_name` | `lucas_eu_2009` — FK to the campaign's sampling log |
| `provision_id__provision_name` | `foss xds rca` |
| `name` | `<sampling_log_name>@<provision_name>` — `lucas_eu_2009@foss xds rca` |
| `preparation_id__preparation_name` / `preservation_id__preservation_name` | `ds2` |
| `storage_id__storage_name` | `amb` (ambient) |
| `laboratory` | `1` — lab-based scanning |

This `name` value is the foreign key referenced by `observation_log_id__observation_log_name` in
every spectral observation record.

### Observations

One observation record per sample. Unlike the lab indicators above, the `@diffuse reflectance`
value here is an array, stored in `observation.observation_measurement_array` rather than
`observation.observation_measurement`.

**Job file**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_observation_spectra.json`

```json
{
  "process": {
    "job_folder": "import_data/LUCAS_2009/process_spectra/observation",
    "process_sub_folder": "manage_process",
    "pilot_file": "xspatula_add_observation_pilot.txt"
  }
}
```

**Generated by**: `step7_spectra_observation()`. Process file
(`.../process_spectra/observation/manage_process/lucas_eu_2009@foss xds rca_<POINT_ID>@0-20_a_0_none_<date>_observation.json`):

```json
{
  "process": [
    {
      "process": "manage_observation",
      "parameters": {
        "observation_log_id__observation_log_name": "lucas_eu_2009@foss xds rca",
        "sample_id__sample_name": "<POINT_ID>@0-20",
        "provision_id__provision_name": "foss xds rca",
        "subsample": "a",
        "replicate": 0,
        "observed_at": "<date, ISO 8601>",
        "provision_serial_nr_id__provision_serial_nr_name": "lucas 2009",
        "@diffuse reflectance": ["<one float per spc.* column, 1/exp(absorbance)>"]
      }
    }
  ]
}
```

| Parameter | Source | Description |
|---|---|---|
| `observation_log_id__observation_log_name` | fixed | FK to the observation log above |
| `sample_id__sample_name` | `POINT_ID` | FK to the sample record (format `<point_id>@0-20`) — see [Samples explained] |
| `provision_id__provision_name` | fixed | `foss xds rca` |
| `subsample` / `replicate` | fixed | `a` / `0` — LUCAS 2009 ships one scan per sample |
| `observed_at` | `date` column | ISO 8601 timestamp |
| `provision_serial_nr_id__provision_serial_nr_name` | fixed | FK to the spectrometer serial record above |
| `@diffuse reflectance` | `spc.*` columns | Reflectance array, one value per wavelength in the spectrometer's `wavelength_array`, computed as `1 / exp(absorbance)` from the CSV's raw values |

The `@diffuse reflectance` array's column order must match the spectrometer's `wavelength_array`
exactly — both are built from the same `spc.*` column iteration in the source CSV, so this holds
as long as the script isn't modified to reorder one independently of the other.
