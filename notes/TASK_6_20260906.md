## Site architecture (current, authoritative — read this before restructuring anything)

There are exactly **two Jekyll collections**: `_lucas_2009/` and `_machine_learning/`. There is
**no separate collection for anything else** — not dataset metadata, not utility, not sample, not
spectra/observations. That was tried (a standalone `_dataset_meta/` collection, and the original
ask below for a standalone `_utility` collection) and reversed both times: a separate top-level
collection for a *step within* the LUCAS 2009 pipeline put it in main-nav competition with "LUCAS
2009" itself, with no coherent ordering — utility must run before dataset metadata must run before
loading, but as separate main-nav items there's no way to express "this one is actually a sub-step
of that one." The fix, applied consistently every time this came up: fold it into `_lucas_2009/`
as a **reference page**, not a peer collection.

**The pattern for adding new reference material**: a "detail" or "explained" page (not required
reading to follow the runbook) is a file inside `_lucas_2009/` (or `_machine_learning/`), with
`sidebar: nav: "lucas_2009"` in its front matter (same key regardless of which of the two
collections it's physically in — see below), added to the `Reference` group in
`_data/navigation.yml`'s `lucas_2009:` key, added to `_data/story_order.yml` in the reference
block (after the four runbook steps, before the machine learning pages), and added to
`_config.yml`'s `nav_order.lucas_2009` list. It does **not** get a `main_navigation` or `main:`
(top navbar) entry — those are reserved for the handful of true entry points (currently: Setup
Xspatula, LUCAS 2009, Machine learning).

**Why `_machine_learning/` is a separate collection but doesn't act like one**: its pages use
`permalink: /lucas_2009/machine_learning/...` (nested under the LUCAS 2009 URL prefix) and
`sidebar: nav: "lucas_2009"` (the *same* navigation key as every `_lucas_2009/` page). Since
`_data/navigation.yml`'s `lucas_2009:` key has three top-level entries (`Seed LUCAS data`,
`Reference`, `Machine learning`), any page — from either collection — that sets `sidebar: nav:
"lucas_2009"` renders all three headed groups. This is the mechanism to reuse if a third
sub-collection is ever needed: give it its own Jekyll collection (for its own `_config.yml`
`nav_order` and content directory), but point its `sidebar.nav` at `"lucas_2009"` and add a fourth
group to that key in `navigation.yml` rather than inventing a new sidebar key or top-nav entry.

**`_data/story_order.yml`** drives previous/next pagination (overriding Jekyll's default
per-collection order — see `_includes/post_pagination.html`) and is intentionally flat across both
collections: runbook steps, then every reference page, then the three ML pages. Keep new pages in
it or they silently get no previous/next (safe, but easy to forget).

**Current full page list** (as of 2026-09-06): `_lucas_2009/` — `synopsis`, `prepare_data`,
`insert_utility`, `insert_dataset_meta`, `load_lucas_2009` (the four required runbook steps, in
this order), `dataset_meta_explained`, `utility_explained`, `utility_inherit_auto_explained`,
`samples_explained`, `observations_explained` (reference). `_machine_learning/` —
`explore_select_data`, `ml_preprocess`, `ml_model`.
