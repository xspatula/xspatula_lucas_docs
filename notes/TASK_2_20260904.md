# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. The initial CLAUDE.md is saved as `.claude/CLAUDE_version1_20260904.md`. This file is an add-on with extended tasks.

## Task 1 - Navigation

The `main` navigation contains headings that link directly to `https://xspatula.github.io/xspatula_core_docs`:
- Xspatula framework
- Setup DB
- Setup processes
- Add user data
- Audit
- Community
- Building

I would like these to be removed from the main navigation and instead only appear in the left columns - as they now also are under the `main_navigation` item (in `_data/navigation.yml`).

Then, if possible, I would like to have 2 left column lists, each with its own (bold) header:
1. Setup Xspatula [Xspatula framework, Setup DB, Setup processes, Add user data, Audit, Community, Building]
2. Seed LUCAS data [Dataset meta, Sample, Laboratory, Spectra, LUCAS 2009, About]

The `main` navigation should then contain the same entries as 2.  [Dataset meta, Sample, Laboratory, Spectra, LUCAS 2009, About].

## Task 2 - Page footer Previous - Next

Each published page by default gets a footer with buttons for [previous] and [next] (automatically done by the Jekyll theme). Either remove these completely (easier) or force them to follow the story line both within each collection and for the last item in a collection to the first item of the next collection (better, but more complex).

**Task 2**: Jekyll's built-in `page.previous`/`page.next` (used by the theme's
`_includes/post_pagination.html`) only walk a single collection in default alphabetical order
(none of our pages set `date`) — that doesn't match the actual reading order, which crosses
collections and revisits `dataset_meta` mid-way through the `lucas_2009` walkthrough. Solved with:

- `_data/story_order.yml` — a flat, hand-maintained list of every page's permalink in the order
  the pages' own cross-links actually walk a reader through (starts at `/lucas_2009/`, dips into
  `dataset_meta`, back to `lucas_2009`, then `sample`, then `spectra`). A page not listed here
  silently gets no previous/next rather than a wrong one — keep this in sync when adding pages.
- `_includes/post_pagination.html` — overrides the theme's include of the same name (local
  `_includes/` wins over the theme gem's). Looks up the current page's position in
  `site.data.story_order` and links to the previous/last entries, with `site.documents | where:
  "url", ... | first` for each link's title tooltip.

Verified by inspecting rendered `_site/**/index.html`: cross-collection links resolve correctly
(e.g. `dataset_meta/manage_campaign` → next → `lucas_2009/insert_utility`), endpoints are properly
disabled (`href="#"`), and pages outside the collections (e.g. `index.html`) correctly get no
pagination nav at all.
