## Project Purpose

`xspatula_lucas_docs` is a documentation site written in Markdown using the Jekyll theme Minimal
Mistakes (https://mmistakes.github.io/minimal-mistakes/) for the database-integrated Xspatula
framework project written in Python in the sibling repo `xspatula_lucas`. `xspatula_lucas` is an
excerpt of the sibling project `xspatula_ai4sh`, documented in the sibling repo
`xspatula_ai4sh_docs`. `xspatula_ai4sh` is built from data that cannot be publicly released at the
moment, whereas `xspatula_lucas` is built from published data (the LUCAS soil sampling
campaigns). This repo is the public manual/instruction site for using Xspatula with LUCAS data —
no reference to the AI4SH project's own data may appear here.

## Site architecture (inherited from `xspatula_core_docs`)

- **Engine**: Jekyll with the Minimal Mistakes theme, pinned via `Gemfile`
  (`gem "minimal-mistakes-jekyll", "4.27.3"`, local install — not `remote_theme`).
- **Serve locally**: `bundle exec jekyll serve --config _config.yml,_config_local.yml`.
- **Build**: `bundle exec jekyll build`.
- **Content = Jekyll collections**, one directory per top-level nav section, each with
  `output: true` in `_config.yml` and a page order list under `nav_order:`. Every page needs
  Jekyll front matter (`layout`, `title`, `categories`, `tags`) and `sidebar: { nav: "<key>" }`.
- **Navigation** is hand-maintained in `_data/navigation.yml` — a new collection is invisible
  until it's added there too. External (core-docs) links go in the same file as plain URLs.
- **Search**: Lunr, client-side, full content (`search_full_content: true`).
- `_site/` and `.jekyll-cache/` are build output — never hand-edit. Copy `xspatula_core_docs`'s
  `.gitignore` pattern (`_site/`, `.jekyll-cache/`, `.sass-cache/`, `.bundle/`, `vendor/`,
  `Gemfile.lock`, `.DS_Store`) — do not perpetuate `setup_core_db_docs`'s untracked-artifacts
  problem. **Do** track `notes/`, per the Important notes below.
