The observation log links the campaign's sampling log to the spectrometer's provision — one
record for all FOSS XDS RCA scans in the LUCAS 2009 campaign.

## Prerequisites

- [Manage spectrometer] must be complete.
- The campaign and sampling log must already exist — see
  [LUCAS 2009 → Load campaign][load_campaign].

## Notebook cell

In `load_LUCAS.ipynb`, the **Manage LUCAS spectra observation logs** cell runs:

```python
job_file = 'import_data/LUCAS_2009/job_LUCAS_2009_observation_log_spectra.json'

structured_process_D, scheme_params_D = Initiate_process(notebook_path, scheme_file, job_file)

if structured_process_D is not None:
    Run_process(structured_process_D, scheme_params_D)
```

## Job file

**Path**: `xspatula_lucas/lucas/import_data/LUCAS_2009/job_LUCAS_2009_observation_log_spectra.json`

## Parameters

| Parameter | Description |
|---|---|
| `sampling_log_id__sampling_log_name` | `lucas_eu_2009` — FK to the campaign's sampling log |
| `provision_id__provision_name` | `foss xds rca` |
| `name` | `<sampling_log_name>@<provision_name>` — `lucas_eu_2009@foss xds rca` |
| `preparation_id__preparation_name` / `preservation_id__preservation_name` | `ds2` |
| `storage_id__storage_name` | `amb` (ambient) |
| `laboratory` | `1` — lab-based scanning |

This `name` value is the foreign key referenced by `observation_log_id__observation_log_name` in
every spectral [observation][Manage observation] record.
